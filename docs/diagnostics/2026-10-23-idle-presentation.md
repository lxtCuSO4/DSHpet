# 2026-10-23：继续核查待机换层后的桌面空帧

## 本轮结论

在本机 Windows 10、Electron 43.3.0 / Chromium 150、软件合成与 1.5 倍缩放下，
**`opacity` 控制的双视频显隐交接是循环边界消失的已验证触发路径**。
同一素材、同一安装 helper、同一双视频加载和结束事件流程，只将显隐方式改为 `visibility`，
8 个观测循环点没有边界空帧；回切原 `opacity` 后，8 个循环点中再次有 6 个出现空帧。

结合原进程观测，问题定位到视频图层交接与 Electron/Windows 透明窗口最终呈现这一段。
不是素材自带透明帧；也没有观察到 JS 同时把两层 opacity 设为 0。
尚未追踪到 Chromium/Electron/Windows 的具体底层函数，不能把某个底层 API 写成已证明的根因。
本轮仅在临时诊断实例中改变 CSS；常用桌宠的安装文件与播放逻辑未修改，原进程未重启。

## 原进程：同时观察内部输出与两条桌面路径

先在可销毁的 Electron 进程验证本机 inspector 接入，再对 PID 27980 临时挂入观察器。
没有暂停或重启进程。直接读取运行中的 CSSOM，确认 `transition:none`、普通待机 `loop=false`，
不再仅依靠磁盘文件和时间戳推断。

记录以下边界：媒体事件、class/style 变化、RAF、视频帧回调、窗口 bounds/穿透/置顶调用、
helper 合成图像的 alpha；同时用 GDI 和 Desktop Duplication 抓取最终桌面。

| 观测 | 范围 | GDI 捕获的边界空白样本 | DDA 捕获的边界空白样本 | helper 零 alpha |
| --- | --- | --- | --- | --- |
| 原进程，开启合成帧读回 | 桌面前 120 秒；内部共观测 18 次换层 | 3 | 4 | 0 / 4,315 |
| 原进程，关闭合成帧读回 | 桌面 90 秒，与内部日志重叠；9 次纯待机换层 | 3 | 5 | 未订阅 |

第一组两条桌面路径有两次命中同一循环边界。示例：

| 路径 | 视频内 PTS | 内容 |
| --- | --- | --- |
| GDI | 19.483333 秒 | 角色消失，其他页面保持可见 |
| DDA | 19.250000 秒 | 同一次循环边界角色消失，其他页面保持可见 |

两条录制起点不同，不能直接比较 PTS。FFmpeg 日志到达时间将这两个样本关联到同一
`switchTo`：Unix 毫秒 1792741025632；对应抓屏日志到达时间分别为 1792741025682 与
1792741025678。日志到达时间有缓冲、PTS 取整和一个样本左右的配准误差，只用于识别同一边界。

该边界附近内部采得的 alpha 仍约 5.34M，新层已经有首帧视频回调；CSS 记录是一层 1、一层 0。
其他桌面空白附近同样没有窗口移动、缩放、穿透或置顶方法调用（检查 ±150 毫秒）。
说明“媒体未解出首帧”“JS 同时隐藏两层”“恰好移动窗口”均缺少本轮支持。
内部订阅是离散输出采样，不足以证明每个瞬间都正常，但足以说明仅看内部 alpha 会漏掉桌面问题。

关闭读回后，纯待机循环仍有桌面空白。第二轮开始时发生过拖拽，已将那一段排除，
只使用随后位置固定、动画为待机、dragging=false 的 90 秒重叠区间。
此时底层为非白色桌面，采用素材全程不透明像素掩码比对；普通帧误差约 1～2/255，
消失样本约 96～103/255，排除把变化的桌面背景误当成素材异常。

## 独立实例的单变量对照与反向验证

实例均使用已安装 helper、同一个真实待机 WebM、bridge 模拟宿主、size 420、scale 1.5、
软件合成、固定左上角、点击穿透和相同采样工具。每次 85 秒探针、约 82 秒 DDA 录制，
覆盖 8 个循环点。按顺序运行，并回看高残差候选帧。

| 条件 | 变化 | 边界消失次数 |
| --- | --- | --- |
| 原逻辑 A | `opacity:0/1`、双视频换层 | 6 / 8 |
| 原生循环 | 仅当前视频 `loop=true`，不再换层 | 0 / 8 |
| CSS 显隐对照 B | 同样双视频换层，仅改为 `visibility:hidden/visible`，opacity 固定 1 | 0 / 8 |
| 恢复原逻辑 A | 再次使用原 `opacity:0/1` | 6 / 8 |

第二次 A 有一个边界连续捕获到两个空白样本，其余为空白单样本。
B 保留媒体重载、`loadeddata` 交接、暂停旧层、播放新层和结束后继续选动画，
因此比“改成原生循环”更能将差异收窄到 CSS 显隐机制。B 没有使用淡化或时间混帧。

B 仅在临时实例注入以下诊断样式，未写入安装或源码应用文件：

```css
video.pet-video { opacity: 1 !important; visibility: hidden !important; }
video.pet-video.is-front { visibility: visible !important; }
```

视频中的外部事件单独记录，不能都算作循环故障或都算作正常：

- 第一次 A 在 43.767 秒有全桌面变暗，角色仍可见，属于外部遮罩事件。
- 原生循环在 42.867～42.883、44.000～44.400 秒有同类变暗，均不在循环点。
- B 在 37.017～37.550 秒发生整个应用背景切回桌面的事件，其他窗口也消失，随后恢复；
  不在循环点，也不能宣称整段视频没有任何消失。
- 第二次 A 在 62.183～62.283 秒同样切回桌面，独立于约 19.517、29.517、39.533、
  49.550、59.550、79.567 秒的六次循环空帧。

本轮不是同屏随机化统计实验，控制组仍有外部桌面操作，样本量也有限。
A/B/A 结果支持本机上的触发路径和候选规避方式，不等于所有系统、所有动画都已修复。
